# 深度研究交付路径分流

`deep_research` 是研究过程技能，不是某一种固定文件格式的生成器。先完成问题定义、检索、核验与证据整理，再根据最终交付物切换到合适的包装路径。

## 一、核心原则

- 默认先沉淀 `research-plan.md` 与 `evidence-ledger.md`
- 交付格式由用户意图决定，优先复用现有 skill 完成最终包装
- 最终文件名按任务主题语义命名

## 二、交付路径表

| 用户最终要什么 | 何时选择 | 本技能负责什么 | 后续路径 |
| --- | --- | --- | --- |
| 聊天内结论 / 无文件 | 用户只要结论、对比、建议，不要求落盘 | 研究、核验、直接回答 | 不生成文件 |
| HTML 研究稿 | 用户明确要求网页稿、在线阅读稿、HTML 预览或最终 HTML | 研究、证据台账、HTML 正文 | 留在本技能内，阅读 `references/html-report.md` |
| 通用 Word 报告 | 用户要 Word / 文档 / 报告 | 研究、证据台账、内容组织 | 切换到 `skills/docx/SKILL.md` |
| PPT / 幻灯片 | 用户要汇报 deck、路演稿、演示文稿、课件 | 研究、证据台账、页级结构与故事线 | 切换到 `skills/pptx/SKILL.md` |
| PDF | 用户明确要 `.pdf` 最终稿 | 研究、证据台账、内容结构 | 切换到 `skills/pdf/SKILL.md` |
| Excel / 表格 / CSV | 用户要表格、数据清单、对比矩阵、字段化交付 | 研究、证据台账、字段定义与数据表内容 | 切换到 `skills/xlsx/SKILL.md` |
| WPS 云文档 | 用户给出 WPS 链接，或要求上传 / 下载云端文件 | 先完成本地研究稿或最终文件 | 按需切换到 `skills/wps/SKILL.md` |

## 三、切换规则

### 1. 留在 `deep_research` 内的路径

只有以下路径继续留在本技能内执行最终包装：

- HTML 最终稿或 HTML 预览稿

### 2. 交给其他技能的路径

以下路径一律先在本技能内完成研究，再把最终包装交给现有 skill：

- `docx`
- `pptx`
- `pdf`
- `xlsx`
- `wps`

切换前至少保证：

- 研究问题与交付目标已经稳定
- `evidence-ledger.md` 已经能支撑正文主结论
- 关键数字、日期、名称、版本已核验
- 已明确最终交付物的结构，而不是只有散碎笔记

## 四、路径对应的最小中间件

- 所有正式研究任务：`research-plan.md`、`evidence-ledger.md`
- HTML 路径：再加 `report.html`
- 其他包装路径：由对应 skill 决定是否需要 HTML、脚本、中间表或模板文件

## 五、硬规则

- PPT / PDF / XLSX 的生成细节交给现有 skill
- 如果用户没有指定格式，但明确说"生成文档 / 报告"，默认仍可转给 `docx` skill；如果用户明确说 PPT / PDF / 表格，则必须按目标格式分流
