# 章节打法

本文件用于说明不同学术章节各自该完成什么，不该完成什么。仅在进入学术路径且需要分节起草、重写或 reviewer pass 时读取。

## 一、Abstract

必须回答：

- 研究问题是什么
- 方法做了什么
- 证据来自什么
- 得到什么结果或结论

常见问题：

- 只写背景，不写方法
- 只写亮点，不写证据边界
- 用宣传语替代结果描述

## 二、Introduction

推荐顺序：

1. 问题和重要性
2. 现有方法的缺口
3. 你的核心做法
4. 为什么你的做法值得相信
5. 贡献列表或贡献段

常见问题：

- 背景铺垫太长
- 贡献说太多，但实验没有兑现
- 把 Related Work 的内容提前塞进来

## 三、Related Work

写法：

- 按主题、方法路线、应用场景或问题设定分组
- 解释已有工作和本文的差异
- 交代本文放在哪条线上

常见问题：

- 按作者堆砌
- 只写别人做了什么，不写为什么与你不同
- 引用未核验

## 四、Method

重点：

- 问题设定
- 整体流程
- 核心模块
- 关键设计选择与原因

常见问题：

- 一上来堆细节，主流程不清
- 定义和符号前后不一致
- 复现关键信息缺失

## 五、Experiments

重点：

- setup 是否足够支撑 claim
- 主结果是否回答贡献
- ablation 是否解释关键设计
- failure case / limitation 是否需要保留

常见问题：

- 把所有表格逐条报数
- 只报提升，不说代价和边界
- 将未显著的结果说成“显著优于”

## 六、Conclusion

重点：

- 回答本文真正得到了什么
- 适用边界和限制
- 后续工作点到为止

常见问题：

- 重复摘要
- 用空话收尾
- 引入正文中没论证过的新 claim

## 七、Reviewer Pass

重点看：

- 新意是否站得住
- 实验是否充分
- 引言承诺与实验兑现是否一致
- 术语、符号、设置是否前后一致

reviewer pass 的职责是找风险，不是做文学润色。
