## HTML PPT 逐页生成指南

### 第1步：视觉设计
根据用户选定的风格，进行视觉设计。
`design/` 目录中提供了几种风格预设供参考。您可以选择并阅读最匹配的预设文件。**以下所有维度均基于参考来源的默认指导；用户的明确要求始终优先。**
| 文件 | 适用场景 |
|---|---|
| `design/business_insight.md` | 券商研究报告、行业研究、市场调研、竞争分析、战略咨询 |
| `design/academic.md` | 论文答辩、组会汇报、科研项目报告 |
| `design/promotion.md` | 品牌发布、营销活动、艺术/时尚/文化展示 |
| `design/education.md` | 中小学/高等教育课件、学生课堂演示、企业培训、教育讲座 |
| `design/work_report.md` | 绩效考核、工作总结、国有企业报告 |
| `design/strategic.md` | 项目提案、商业计划、融资路演、战略规划报告 |
| `design/general.md` | 当用户需求不符合以上任何场景时使用 |

- 如果用户场景明确符合某个预设，直接阅读对应文件并遵循其指导
- 如果用户场景介于多个预设之间，选择最接近的一个作为参考
在阅读完参考后，结合用户选择的**风格方案**，输出`design.md` 文件
`design.md` 必须包含以下内容（按章节顺序写入）：
- **1. 内容分析与叙事设计**：受众、情绪、核心论点、叙事框架（如金字塔/SCQA）与节奏设计
- **2. 视觉设计落地**：直接继承用户选定方案的风格句、设计哲学，并定义一个贯穿全套的视觉母题（如圆角框架、粗体单侧边框），并根据场景（教育/商业/产品/技术）给出具体的视觉语言落地
- **3. Design Token 表**：将用户选定方案的调色板，字体方案展开为完整的 CSS 变量表，作为后续生成html ppt页的唯一色彩来源。除非用户指定，否则**任何正文字体不小于22px**
- **4. Bold Choices**：直接复制用户选定方案的 3-5 个 Bold Choices（非协商的视觉承诺），生成内容页html时必须逐条兑现
- **5. 图片决策表**：直接复制风格探索阶段的图片决策表，此表是全流程唯一的图片策略来源

- 注意：**视觉设计应以内容为基础——内容少并不意味着设计可以简单；反而要求更高端、更精致的美感！** 内容越少，设计越需要提升精致感。如果内容偏稀疏，或每页文字量较少，就需要更多装饰元素、图片和更精细的网格布局来确保高端的视觉体验。

### 第2步：内容大纲设计
根据视觉设计中的信息规范，输出整份ppt的大纲 `outline.md` 文件：

1. 大纲第一部分，整体规划，包含以下内容
- **内容分析与叙事设计**：
基于 `design.md` 里这部分内容再微调，要考虑以下几点
明确核心：受众是谁？场景是什么？核心情绪（权威/激情/克制）？唯一要记住的结论是什么？
叙事结构：如何开场，如何展开，如何收尾。MECE 原则检验：确保各分论点之间相互独立、完全穷尽。
节奏设计：哪里需要高密度信息，哪里需要留白呼吸，哪里需要视觉冲击。
- **场景感知**：
  - **教育/培训**：强调清晰的层级、步骤图、对比图，减少干扰元素。
  - **商业/汇报**：强调数据可视化、金字塔结构、结论先行，配色沉稳。
  - **产品/发布**：强调大图展示、特性网格、极简大字，视觉冲击力强。
  - **技术/架构**：强调系统图、代码块高亮、逻辑流程，配色科技感。
- **页数规划**：
根据用户提供的文档或搜索资料的文本量，确定合适的幻灯片总数。内容要丰富详实，不要因为压缩内容而损失信息密度：

| 提供文本量 | 建议页数 | 对应篇幅 |
|-----------|---------|---------|
| < 8000 字 | 15–20 页 | 短篇幅 |
| 8000–12000 字 | 25–30 页 | 中篇幅 |
| > 12000 字 | 35–40 页 | 长篇幅 |

若用户未提供具体资料，根据主题复杂度和受众预期自行判断，但不得少于 12 页。
在写入大纲文件时，先确定合适的 PPT 篇幅，再开始写入大纲内容。

> **注意**：确定篇幅时，向用户说明的是一个页数范围（如"约 25–30 页"），而不是一个精确数字。实际页数会在大纲完成后自然确定，过早锁死页数反而会导致内容被强行填充或裁剪。

2. 大纲第二部分，逐页编排内容大纲，遵循以下要求规划每页大纲

- **内容量评估铁律**：规划每页内容时，必须评估每页的核心内容量是否足以撑满一页。
  - **研报场景单页内容量底线**：对于行业研报、白皮书等高密度场景，单页大纲必须包含以下组合之一，严禁出现内容单薄的页面：
  组合 A：1 个主图表（ECharts） + 1 段完整的分析结论（50-100字） + 3-4 个辅助数据卡片
  组合 B：2-3 个并排的小图表 + 对应的分析要点
  组合 C：1 个多行多列的复杂数据表格 + 底部总结说明
  如果原始素材内容不足以支撑上述组合，必须通过逻辑推演补充合理的占位数据/分析，或将多个单薄的页面合并为一页。
  - **演讲场景**：如果一页的内容只有 2-3 个要点且无法扩展，**必须与相邻页合并**，或者补充相关图表/对比数据，绝不允许出现内容单薄导致大面积留白的页面。
- **布局与空间分配原则**：每页 HTML 的空间结构遵循**Grid 定骨架，Flex 分比例**：
  - **Grid** 一是负责将 slide-container 切成垂直分区（标题带 / 主内容区 / 页脚带），每个分区边界预先锁死。二是在主内容区内用网格编排好要展示的子内容块。grid布局的核心目的是确保整页视觉上的对齐，内容区块之间不重叠且合理占据整页html的布局空间（1280*720px）
  - **Flex** 负责在子内容区块内按比例分配空间：子内容区块应多用flex流式布局，多列用 `flex:1` 等分宽度，多行用 `justify-content: space-evenly` 或 `flex:1` 撑满高度。总之，flex的核心目的是让每个子内容区块也重心居中，并减少大量留白空间。
  - **禁忌** 主内容区没有明确的空间分配指令时，子项默认堆顶、下方空洞——这是最常见的视觉重心偏移的问题。
- **逐页大纲格式**：每页大纲必须包含以下字段：

```
## 01 标题页
- 类型：标题页
- 视觉焦点：主标题大字
- 风格关联：深色背景 + 强调色装饰线
- 核心内容：(简述该页要传达的核心信息)
- 配图：背景图(决策表) / 根据内容配图 / CSS纯视觉 / 无
- 布局规划：页面层 → 枚举 slide-container 所有直接子元素及 grid 行轨道；主内容层 → 枚举主内容区所有视觉子元素（含分隔符等中间元素）及列/行轨道。每层元素数与轨道数一一对应。
- 字体方案：主标题 XXpx / 副标题 XXpx / 正文 XXpx / 辅助 XXpx（须满足：内容块≤2个→正文≥32px；≤3个→≥28px；≤4个→≥26px；≥5个→≥22px）
```

**逐页大纲各字段说明**：
[字体方案]需列出本页各层级的具体字号，并标注内容块数量以确认是否满足字号自适应规则。
[布局规划]要详细说明本页将如何排版布局，写两层：页面层和主内容层，每层枚举所有视觉子元素并对应轨道，元素数与轨道数必须一致；写 HTML 时直接按此执行。
[配图]直接引用图片决策表的结论。有图的页面必须使用左右分栏（图文隔离铁律）。

### 第3步：逐页生成PPT的HTML
再次读取 **`html_slide_technical_design.md`** 文件，每页生成的html需严格遵循其中的 HTML 技术规范与设计指导。

若风格探索阶段已生成封面 HTML，直接沿用无需重新生成；将封面页拷贝至`pages/`目录下，作为slide_01.html即可。

**写入方式**：使用工具 `write_file` 将完整 HTML写入`slide_xxx.html`文件。**禁止**使用 Python 脚本写入 HTML 文件。
**编码注意**：避免在代码、注释、字符串中使用特殊 Unicode 字符，使用标准 ASCII 或常见中文字符。

#### 单页实现节奏

1. 按`outline.md`文件中各页的配图决策判断是否需要生图，如果需要先生图
2. 根据各页的布局规划，风格关联，视觉焦点，核心内容，思考 HTML 要填充的内容
3. 兑现 Bold Choices：检查这页是否有机会兑现某个 Bold Choice
4. 写入这页的html文件
5. **布局自检**（写入文件后检查，不合格须修正）：
   - 主内容区容器是否有 `justify-content: center`？（对照 `html_slide_technical_design.md` 「防内容贴顶铁律」）
   - 本页内容块数量是多少？字号是否已按「字号自适应规则」对应档位调整？（≤ 4 个要点时不得使用 22px 最小值）
   - 脑中将页面三等分，内容视觉重心是否落在中间 1/3？
   - 内容块 ≤ 3 个时，是否有装饰元素填充画幅？（纯文字 + 空白背景不可接受）

### 第4步：跑版校验

所有幻灯片 HTML 文件生成完毕后，调用 `check_slides_layout` 对全部文件进行**HTML 合法性**和**跑版**检测。

#### 执行方式：

```python
import sys, os
sys.path.insert(0, os.path.join(os.getenv('SKILL_PATH'), 'pptx', 'scripts'))
from generate_pptx import check_slides_layout
slides = [
    # ...需要检查的 html 文件路径
]
print(check_slides_layout(slides))
```

### 第5步：导出 PPTX

所有幻灯片 HTML 文件校验通过后，调用 `html_slide_to_pptx` 导出 PPTX。

```python
import sys, os
sys.path.insert(0, os.path.join(os.getenv('SKILL_PATH'), 'pptx', 'scripts'))
from generate_pptx import html_slide_to_pptx
print(html_slide_to_pptx(
    html_files=[
        # ...需要导出的 html 文件路径
    ],
    output_path="保存路径",
))
```

## 最终强调

| 原则 | 含义 |
|------|------|
| **严格按步骤执行，禁止跳步** | 必须完成「视觉设计 → 内容大纲」两步后，再进入逐页 HTML 生成。禁止在大纲未完成时提前动手写 HTML，否则布局和风格无从对齐 |
| **布局是第一优先级** | 每页 HTML 开始写入前，先想好这页的布局是否符合要求，视觉重心有没有居中，整页留白是否过多，各内容区块间有没有对齐 |
| **字号随内容量浮动，不得死用最小值** | 内容块 ≤ 4 个时，正文字号须按自适应规则上调（≤2→≥32px / 3个→≥28px / 4个→≥26px）；用字号和间距撑满空间，而不是用留白将就 |
