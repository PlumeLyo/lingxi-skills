# PPT 风格探索指南

工作流：**设计 3 套候选风格 → 生成封面 HTML → 截图展示 → 用户选择 → 进入生成阶段**。

---

## HTML 技术规范

所有 HTML 生成（封面预览、后续逐页实现）均须遵守本章全部规则。

### 版面契约（防跑版：固定画布 / 无叠字 / 无滚动）

以下三条与「美观」并列，**违反任一条即视为跑版**，必须在交付前消除。

1. **固定画布 1280×720px（16:9）**  
   - `html`、`body`、`.slide-container` 在 CSS 中写死为 `width:1280px; height:720px;`（可用 `max-width`/`max-height` 同值兜底）。  
   - 整页视觉内容只存在于这一矩形内，**不得**依赖浏览器窗口缩放或大于画布的隐式尺寸撑开页面。

2. **禁止滚动与「滑动查看」**  
   - `html, body { overflow: hidden; }`，`.slide-container { overflow: hidden; }`。  
   - 不得出现纵向/横向滚动条，不得用 `overflow: auto|scroll` 在页内藏第二屏内容。内容过多时**拆页或减字**，绝不靠滚动解决。

3. **禁止可感知的文字/正文块互相遮挡**  
   - 优先用 **flex / grid + 固定 gap** 排版，保证块与块之间留白可预期。  
   - 若使用 `position: absolute`，必须为每个块预留**不重叠**的矩形区域（含行高与多行折行后的高度）；**禁止**为「塞下更多字」把多块文字压到同一视觉区域。  
   - 装饰性背景层（纯色、渐变、几何纹理、半透明水印、半透明大字号背景标题）可与文字层叠，但**带可读文本的块之间**矩形区域不得重叠。此外，为保证阅读清晰度，除背景相关的装饰性元素外，所有实质性文本的不透明度不得低于 80%。

### HTML 结构与命名约定

- 每页幻灯片生成一个**完整独立的 HTML 文件**，CSS/JS 全部内联，不依赖外部文件（CDN 资源除外）
- HTML 文件命名范式：`slide_xxx.html`，**必须以 `slide_` 开头**
- class 命名使用 `slide-` 前缀（如 `slide-title`、`slide-card`），避免与 Tailwind 冲突

### 布局

- 页面固定尺寸 **1280×720px**（16:9），所有元素必须在此范围内，不得溢出
- 使用 `slide-container` 作为最外层容器；**`.slide-container` 自身**不要用 `padding`（避免与固定 1280×720 叠加算错尺寸）；**子元素**可用 `position:absolute`，但必须满足上文「版面契约」
- 在所有 CSS 之前重置默认样式（`margin: 0; padding: 0; list-style: none; text-decoration: none; box-sizing: border-box;`）
- 采用**水平布局**，始终限制每个元素的高度，禁止垂直堆叠多个图表/图像
- 图像/图表元素必须指定**固定像素**的宽高，禁止使用百分比或 flex 弹性尺寸
- 容器内部用网格布局水平铺满（`justify-content: space-evenly`）；多列内容时列间保留**固定像素**的 `gap` 或 `margin`，避免相邻列文字贴在一起重叠
- **单行文本（标题、标签、署名等）必须加 `white-space: nowrap`**——防止因容器宽度不足意外换行导致与周围元素重叠。若使用了 `letter-spacing`，同时加 `margin-right: -<letter-spacing值>` 修正右侧多余空白

### 视觉设计

- **禁止**使用圆角卡片、左/右边框强调卡片、阴影框等网页 UI 样式
- **禁止**使用 CSS 动画、`@keyframes`、`transition`、`hover` 效果（静态幻灯片，不是交互网站）
- **尽量减少**卡片样式，数据可视化页面**严禁**使用卡片
- 单页最多使用调色板中的 2-3 种颜色
- 强调色只用于最需要关注的元素（关键数字、标题高亮、核心数据点）

### 资源规范

**仅允许**使用以下三个 CDN，**禁止引用其他任何 JS 库或 CDN**：

```
Tailwind CSS：
<script src="https://qn.cache.wpscdn.cn/copilot-test/copilot-cdn/js/tailwindcss@3.4.17.js"></script>

FontAwesome（图标与文本一一对应，禁止孤立/装饰性图标）：
<link href="https://qn.cache.wpscdn.cn/copilot-test/copilot-cdn/css/fontawesome-free@6.4.0.css" rel="stylesheet" />

ECharts（数据可视化）：
<script src="https://qn.cache.wpscdn.cn/copilot-test/copilot-cdn/js/echarts@5.4.3.min.js"></script>
```

**禁止**引用 Google Fonts（`fonts.googleapis.com`）、jQuery、Bootstrap 等。

### Tailwind CSS 使用限制

- 仅使用 Tailwind 内置 utility class，**禁止**运行时能力：`tailwind.config` 注入、`text/tailwindcss` 样式块、`@layer` / `@apply` 指令、非官方默认 class
- Tailwind Preflight 会重置标题标签样式，必须用高权重选择器或 `!important` 覆盖关键字号：
  - 用 `.slide-container h1 { font-size: 64px !important; }` 而非 `h1 { font-size: 64px; }`
  - 涉及 `font-size`、`font-weight`、`line-height` 时，必要时加 `!important`

### ECharts 使用规范

- 图表容器必须用具有明确像素宽高的父 `div` 包裹（如 `style="width: 600px; height: 360px;"`）
- 每列最多一个图表
- 图表颜色从调色板派生
- **禁止**生成虚构数据；所有数字必须来自可验证来源，并标注数据源

## 设计指导

### 内容密度铁律

- 每页最多 5 个要点（多了拆页，绝不硬塞）
- 标题 ≥ 48px，正文 ≥ 22px，辅助文字 ≥ 18px（1280×720 基准，投影必须清晰）
- 单张幻灯片只传达一个核心信息
- 正文行长不超过页面宽度的 65%
- 每页有且仅有一个视觉重心

### 设计原则

**在实现每个页面前，先思考：**
- **目的**：这页要传达什么核心信息？受众在这页停留的焦点是什么？
- **基调**：贯彻执行该页幻灯片定义的风格句。
- **差异化**：这页的视觉重心是什么？用户会记住的一件事是什么？

关键在于**意图性和整体一致性**，而非盲目追求复杂或简约。

### 美学关注点

#### 字体排版
- 使用确定的展示字体 + 正文字体搭配方案，不得引入其他字体
- 字号层级清晰：标题 ≥ 48px，正文 ≥ 22px，辅助文字 ≥ 18px

#### 色彩与主题
- 主色调搭配鲜明强调色，优于均匀分布的配色
- 使用 CSS 变量保持一致性
- 避免陈词滥调的配色（尤其是白底紫色渐变）

#### 空间构图
- 尝试非对称、对角张力、打破均匀网格的构图，避免所有元素居中平铺
- 慷慨的留白或受控的密度，两者都是有效选择，根据风格句决定

#### 背景与细节
- 创造氛围和深度，而非默认纯色背景
- 可用纯 CSS 实现的纹理效果：渐变叠加、重复线条图案、几何背景、分层透明度、戏剧性阴影

### 核心要求

- **避免通用 AI 美学**：可预测的居中布局、千篇一律的卡片堆叠、缺乏情境特色的配色
- **实现复杂度匹配风格**：厚重风格需要密度和力量感，克制风格需要精准的间距和字号控制
- **每页视觉语言一致**：任意抽出一页，都应能认出它属于这套 PPT

## 1. 设计 3 个候选风格

收到用户的 PPT 请求后，首先进入风格探索流程。

基于主题设计 **3 套一眼可区分** 的方案。禁止用「同一色相 + 微调饱和度/渐变强弱/深浅」冒充三套。

### 差异化约束
1. **色相族必须拉开**：三个方案的主氛围色须落在不同色相区间，主色在色环上的倾向应明显不同，禁止仅用同一主色替换辅色。
2. **质感轴**：为每个方案指定截然不同的画面质感与视觉特效，自由发挥创意，**不得**在三套方案中使用同一种质感或材质表现。
3. **构图与动势**：风格句中必须呈现不同的版式动势与空间布局，禁止三个方案采用同一套骨架仅做换色处理。
4. **字体气质必须分叉**：展示字体与正文字体的组合在三套方案中须呈现完全不同的气质，禁止仅更换字重或字号阶梯却沿用同一对字体。
5. **保守—均衡—大胆 ≠ 三套近似**：光谱上的「保守 / 均衡 / 大胆」应体现在**上述维度上的真实差异**与创意跨度，而不是同一视觉套路的「淡一点 / 默认 / 浓一点」。

**质量**：非复古主题则现代、高冲击；主氛围忌脏灰土色，强调色须亮且饱和。走黑白极简时，用质感或构图补冲击，且仍满足与另两套的色相/质感差异。渐变须服务于已定质感，禁三套同一类软渐变。

每个方案须包含：
- **风格描述**：英文短句（< 20 词）附带括号内中文翻译；要求描述高度独特、视觉效果惊艳的世界级美学设计风格。它应该捕捉定义特征——布局节奏、纹理或光线提示。禁止所有模糊的形容词，如"干净"、"现代"、"优雅"、"简约"、"柔和"、"精致"。美学必须立即可识别，不可与通用企业或常见设计趋势混淆。
- **调色板**：3–4 个 hex 色值及角色（背景色 / 主文字色 / 强调色 / 次要色），强调色须高饱和且可参与渐变。
- **字体方案**：展示字体（大标题用）+ 正文字体（正文用）的搭配方案，并说明与美学风格的关联。仅允许以下 Web-safe 中文系统字体栈：  
`"SimSun"` / `"SimHei"` / `"Microsoft YaHei"` / `"NSimSun"` / `"KaiTi"` / `"FangSong"` / `"宋体"` / `"黑体"` / `"微软雅黑"` / `"新宋体"` / `"楷体"` / `"仿宋"` / `"隶书"` / `"幼圆"` / `"华文中宋"`

三套方案须覆盖从**保守到激进**的接受度光谱（沉稳克制 / 均衡叙事 / 大胆前卫），但光谱差异须由正交维度共同体现，而非同一套路的轻中重三档。

## 2. 生成风格封面页（HTML）

*必须为每个方案生成封面 HTML 文件，逐方案交替输出：先输出风格描述文字 → 再写入该方案的封面 HTML → 完成后再做下一套。
单个方案的输出流程：
1. 输出文字，包含以下三项：
   - `方案 {N}：{英文风格描述} （{中文风格描述}）`
   - 调色板：列出颜色及角色
   - 字体搭配：展示字体 + 正文字体
2. 使用 `write_file` 写入完整 HTML，路径中的**文件名**须为 `slide_*.html`，**禁止使用 Python 脚本写入 HTML 文件**（会导致引号、反斜杠等转义问题）。
3. 完成后再进入下一个方案

## 3. 截图并展示

3 个封面 HTML 全部生成后，调用 `screenshot_slides` 一次性截图：

```python
import os, sys
sys.path.insert(0, os.path.join(os.environ["SKILL_PATH"], "pptx", "scripts"))
from generate_pptx import screenshot_slides

print(screenshot_slides([
    # ...各风格封面页 html 文件路径
]))
```

截图完成后，按以下格式总结各风格展示给用户，每个方案仅包含两项，不附加任何额外说明：
1. 一行风格描述：`方案 {N}：{中文风格描述}`
2. 紧接使用 **`sharing_files`** 格式输出截图链接

输出完方案 1 后，再输出方案 2，依此类推。
